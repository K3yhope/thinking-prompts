# 学习：反向拆解

## 适用场景

- 用户想拆解优秀产品、网页、方案、流程、数据看板或其他成品。
- 用户说“这个东西好在哪”“我想模仿学习”“帮我提炼可复用规律”。

## 输出强度

- 轻量：说明它解决什么问题，提炼 3 条最关键规律和一个小练习。
- 标准：完整分析服务对象、目标、结构、关键选择、完成标准、迁移规律和操作清单。
- 深度：增加更多质量差距分析、迁移边界、反例和分阶段练习。

## 追问与初版判断

如果用户没有说明“想学会什么”，但范例足够清楚，可以先做通用拆解，并列出本次默认学习目标。若学习目标会显著影响拆解重点，先问一个关键问题。

## 模板复用输出

用户要求可复制 Prompt 时，输出反向拆解的定制模板，不直接拆解案例。

## 模式切换

如果用户从案例拆解转为判断案例中的事实是否成立，切换到事实核查；如果用户要研究这个案例所在行业或竞品格局，切换到横纵分析法。

## 执行规则

先用一句话说明范例解决了什么问题，再拆解它为什么有效：

1. 服务谁，目标是什么。
2. 采用了什么结构或流程。
3. 哪些关键选择拉开质量差距。
4. 完成标准是什么。
5. 哪些规律可以迁移，哪些细节只适合这个案例。

最后给出 3 到 5 条可复用规律、一份操作清单、一个最值得先尝试的小练习。

## 原 Prompt 模板

```text
我想拆解的优秀范例是：【粘贴产品页面、网页、方案、流程说明、数据看板或其他成品】。我想学会的是：【填写你希望从中学会什么】。请先用一句话说明它解决了什么问题，再反向拆解它为什么有效。重点分析：1. 它服务谁，目标是什么；2. 它采用了什么结构或流程；3. 哪些关键选择拉开了质量差距；4. 它的完成标准是什么；5. 哪些规律可以迁移，哪些细节只适合这个案例。最后请给我：1. 提炼3到5条可复用规律；2. 一份可以照着执行的操作清单；3. 一个最值得先尝试的小练习。
```
